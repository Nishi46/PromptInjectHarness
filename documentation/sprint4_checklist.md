# Sprint 4 Checklist — Adaptive Attacks (E?)

Granular sub-steps for each task in Sprint 4 of [sprint_planning.md](sprint_planning.md). Check items off as you go; each should produce a concrete artifact (a file, a passing test, a committed config/result). Ordered to respect the `Deps` column in the sprint table — work top to bottom. Grounded in the Sprint 1–3 codebase (`adapters/agentdojo_adapter.py::run_episode`, `adapters/mcp_adapter.py::run_mcp_episode`, `attacks/registry.py`, `attacks/families/*.py`, `mcp/poisoned.py::PoisonedCase`, `trace/db.py` + `trace/schema.sql`, `trace/queries.py`, `sweep/runner.py`, `clients/base.py::ModelClient`) — reread those before starting. Also reread [docs/notes/adaptive_attacks.md](../docs/notes/adaptive_attacks.md) in full: it already documents where this sprint's design (S4-01's discrete feedback, S4-02's LLM mutation, S4-03's per-task round budget) diverges from the Zhan et al. paper it cites. That divergence is real and should be stated plainly in S4-08's writeup, not glossed over.

> **Read this before writing any code.** Every existing execution path runs exactly one static, pre-computed injection payload per episode: `agentdojo_adapter.run_episode` calls `attack.attack(user_task, injection_task)` once and hands the resulting `injections: dict[str, str]` straight to `suite.run_task_with_pipeline`; `mcp_adapter.run_mcp_episode` calls `PoisonedCase.apply(server)` once using the case's fixed `injection_text`. Sprint 4 needs to re-run the *same* (defense, task) pair up to 20 times with a *different* payload each round. Three of the five AgentDojo families (`naive`, `ignore_previous`, `important_instructions`) build their payload from a `FixedJailbreakAttack.jailbreak` template string — but `encoding_obfuscation` computes its payload in Python code (`base64.b64encode(...)`, see `attacks/families/encoding_obfuscation.py`), with no template string to swap. That rules out "mutate the attack object's internal state" as a uniform hook. **The design used throughout this checklist: mutate the *output* of round 1's payload computation, not the attack machinery that produced it**, and plumb a plain override string/dict into `run_episode`/`run_mcp_episode` for every round after the first. This keeps the mutator suite- and family-agnostic (it only ever sees "the current payload text" and "the injection goal", both plain strings) and needs exactly one small, additive parameter on each existing adapter entrypoint — not a rewrite of either. Write this decision down explicitly as the first S4-01 step so nothing downstream re-derives it.

**Cost risk — the big one.** 6 defenses × 5 attacks × 20 rounds × tasks × models multiplies fast. `adaptive-run --sample-fraction 0.01` (S4-05) exists specifically to run a 1% sample and extrapolate the bill *before* launching the full S4-05 sweep. Cut models before you cut rounds; rounds are the scientific claim.

**Watch for:**
- The `encoding_obfuscation` family has no template string to mutate in place — this is why every override is plumbed as a post-hoc string/dict into `run_episode`/`run_mcp_episode`, not as a mutation of attack-object internals (see the preamble). Don't special-case this family; the uniform override design should already cover it.
- A trial is not resumable mid-loop the way `sweep/runner.py`'s episodes are (S4-03) — a process restart re-runs a trial from round 1. Fine at S4-05's cost-capped scale; would need revisiting before scaling this up.
- `_looks_in_family` (S4-02) is a cheap heuristic, not a classifier — it exists only to catch obviously-drifted mutations and fall back safely, not to guarantee every accepted mutation is genuinely in-family. Don't lean on it for anything scored.
- Multi-injection-point AgentDojo tasks get one mutated payload applied identically to every candidate (mirrors `FixedJailbreakAttack`'s own existing behavior) — verify against the real S4-05 task list whether this ever actually matters before assuming it's a non-issue.
